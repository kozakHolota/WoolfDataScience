# Homework 4 — Kafka Sensor Simulation + Spark Streaming

Симуляція IoT-сенсорів будівлі з використанням Apache Kafka.

## Що робить програма

Запускається 5 сенсорів у паралельних тредах. Кожен сенсор генерує випадкові показники температури (25–45°C) та вологості (15–85%) і публікує їх у топік `building_sensors`.

Окремий тред-монітор читає повідомлення з `building_sensors` і, якщо температура перевищує 40°C, публікує алерт у топік `temperature_alerts`.

Ще один тред підписується на `temperature_alerts` і `humidity_alerts` та виводить отримані алерти.

### Вивід у консоль

| Префікс | Подія |
|---------|-------|
| `[PUBLISH]` | Сенсор готує дані до відправки |
| `[SENT]` | Повідомлення успішно доставлено в Kafka |
| `[READ]` | Consumer зчитав повідомлення з топіку |
| `[ALERT]` | Виявлено перевищення температури, публікується алерт |

## Запуск

```bash
docker compose up --build --abort-on-container-exit
```

Флаг `--abort-on-container-exit` автоматично зупиняє Kafka після завершення роботи консумера.

## Архітектура

```
Sensor (x5) ──PUBLISH──> building_sensors ──READ──> catch_exceptions ──ALERT──> temperature_alerts
                                                                                        |
                                                                                      READ
                                                                                        |
                                                                                   get_alerts
```

## Параметри запуску

Задаються через `CMD` у `Dockerfile`:

| Параметр | За замовчуванням | Опис |
|----------|-----------------|------|
| `--iterations` | 20 | Кількість публікацій на сенсор |
| `--sensors_amount` | 5 | Кількість сенсорів |
| `--timeout` | 20 | Кількість циклів моніторингу |
